# 训练营项目对标与选择决策

## 决策

半年采用“一主一展”：

- 主项目：Windows C++ inference runtime workbench（复用并对照 ONNX Runtime 与 llama.cpp）；
- 展示层：调用本地推理 runtime 的离线 Agent/代码审查工具。

高级 C++ 能力通过主项目中的内存、并发、ABI、调试、性能和工程化证据体现。AI 数字人、视频会议和完整 PR Agent 平台只保留为架构参照，不承诺半年内完整实现。

## 为什么调整主次

目标岗位首先是 C++ AI 推理基础设施。如果先做通用 Agent，最容易积累的是编排、协议和应用代码，无法充分证明张量、内存布局、算子、量化、KV Cache、并发调度和性能分析能力。先复现并测量成熟 runtime，再搭建统一工作台和小型自研组件，最后让 Agent 调用它，可以形成从底层到应用的单一证据链。

## 项目达到“可对标”的标准

不是项目名称相同，而是至少覆盖对应核心难点：

- inference runtime workbench：ORT/llama.cpp Adapter、张量/内存实验、调度、取消、batching、metrics、故障注入和 Benchmark；
- Agent 展示层：调用本地 runtime、工具权限、结构化输出、证据引用和人工审批；
- AI 数字人参照：音频/文本输入、推理任务、流式调度、延迟和资源管理；
- 视频会议参照：媒体采集/编码、信令、并发会话、网络异常和资源释放。

每个项目必须固定依赖版本、保留许可证审计、可在 Windows/MSVC 本地构建、可测试、可复盘。展示层不能以调用现成模型服务代替主项目的底层证据。

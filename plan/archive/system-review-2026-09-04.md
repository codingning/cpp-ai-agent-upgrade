# 训练系统评审（2026-09-04）

## 结论

当前仓库已经具备正确的目标意识：按真实进度滚动、强调独立思考、测试、证据和安全边界。但它仍更像一份完整计划，而不是一套能持续运行和判断“是否真的掌握”的训练系统。

优先改进方向是：把每个主题改成“诊断—学习—读源码—实现—验证—复述—间隔复测”的闭环，并把主项目从通用 Agent 调整为 Windows 上的 C++ AI 推理运行时；Agent 作为调用推理运行时的展示层。

|---|---:|---|---|
| 目标与边界 | 4/5 | C++ 推理与 Agent 主次不清 | 推理基础设施优先，高级 C++ 为通用能力线 |

## 为什么不是“先学完再写代码”

纯阅读容易形成识别感，但无法暴露所有权、边界条件、编译错误和调试盲点；完全不预习就编码，又会把训练变成猜测和重复踩坑。默认采用短周期交替：

1. 用 5 分钟闭卷诊断，写下自己的预测；
2. 用 10 分钟阅读主资料，只回答当天的三个问题；
3. 用 15 分钟追踪优秀源码中的一个小切片；
4. 用 20 分钟闭卷实现或修正最小实验；
5. 用 7 分钟运行测试、诊断工具或故障注入；
6. 用 3 分钟记录证据和下一次复测日期。

第一天的代码不是作品，而是基线探针。较难主题按三天展开：第一天理解与微实验，第二天闭卷实现与测试，第三天故障注入、性能对照和复述。

## 完成定义

仓库中的一个主题只有同时满足以下条件才算通过：

- 能在不看答案时解释关键机制和边界；
- 能独立实现最小版本并通过测试；
- 能定位至少一个失败案例；
- 能指出优秀源码中相关设计的位置与取舍；
- 证据已绑定到命令、输出和 commit；
- 7 天后复测仍能通过。21 天复测用于确认长期保持。

## 仍需用户决定

仓库当前没有自身的 `LICENSE`。在用户明确选择许可证前，不替用户授予他人复用权；第三方依赖与模型许可证仍需分别记录。

## 本轮执行修正（2026-09-04）

根据实际复盘，第一周采用降级路径“假资源 → 最小 move-only wrapper → WIL/真实 Windows handle”，WIL 不再是 Day 1 必须理解的门槛；每日任务明确区分核心闭环与可选加餐，默认不超过 60 分钟；推理运行时主线继续保留，但通用高级 C++ 能力域必须独立验收，不能被 Agent 或模型 API 任务替代。

### 🆕 「看不到输出」≠「没执行」—— 进程非正常终止会整块丢掉缓冲（10-12 新立）

- **判据**：`std::cout` / `printf` 是**带缓冲**的。进程被信号/异常杀掉时（崩溃、`abort`、
  堆损坏），缓冲区里还没刷出去的内容**整块丢失**。
  所以崩溃类实验里「只看到前面一点输出」**不代表后面的代码没跑**。
- **10-12 实例（本人的 `day1_unique_ptr.cpp`）**：
  他的代码本身是对的、实验设计也对（两个独立作用域 + ctor/dtor 计数），
  但**原样跑出来只有一个 `8`，然后 `EXITCODE=-1073740940`**，
  三组计数和两个 `sizeof` 全看不见 —— 这会让他误判成「代码没跑 / 我写错了」。
  教练只加一句 `std::cout << std::unitbuf;` 再跑**同一份代码**，立刻拿到完整证据：
  ```
  8
  ctor 1/2/3  dtor 1/2/3        ← unique_ptr<Widget[]>：3 构造 3 析构，正确
  ctor 4/5/6  dtor 4            ← unique_ptr<Widget> 管 new Widget[3]：3 构造只 1 析构，然后死
  ```
  `0xC0000374 = STATUS_HEAP_CORRUPTION`。**泄漏 2 个对象 + 进程当场死。**
- **处置（二选一）**：①`std::cout << std::unitbuf`（C++ 流）或 `fflush(stdout)` / `setbuf(stdout,NULL)`（C）
  ②**把可能崩的块挪到最后**，让前面的输出先刷出去。
- **归族**：这是「界面看到什么 ≠ 代码执行了几次」（09-30 立）的**第四个问法** ——
  前三个问「我观察的量对不对」，这条问**「我观察的通道本身可靠吗」**。
  工具会骗人：09-30 是 DevTools 合并重复日志，10-12 是 stdout 缓冲被丢。


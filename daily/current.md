## 二、W8 第二课 · 内存序（35min）

> 🔴 按 09-28 你立的顺序铁律：**这块你没学过，我先把定义直接给你，再让你跑实验验证。**
> 不让你猜。

### 2.1 先把问题摆出来

昨天 `atomic` 解决的是：**单个变量的读改写不被切开**。
今天要解决的是另一件事：**两个不同变量的操作，在别的线程眼里是什么顺序。**

你写的代码顺序是「先 `x = 1`，再 `y = 1`」。**但别的线程不一定按这个顺序看见。**
原因有两层，**都真实存在**：

- **编译器**可以重排两条无依赖的指令（它只保证单线程内看起来结果一样）
- **CPU** 也可以。x86 有写缓冲（store buffer），一个核的写可以晚一点才被别的核看见

**内存序（memory order）就是你给编译器和 CPU 下的约束**：哪些重排不许做。

### 2.2 四个档位（今天只要求认识前三个 + 默认的那个）

| 写法 | 名字 | 保证什么 |
|---|---|---|
| `memory_order_relaxed` | 松弛 | **只保证这一个变量自己是原子的**，不约束它和别的操作的相对顺序 |
| `memory_order_release`（用在**写**） | 释放 | 这条写**之前**的所有写，不许被重排到它**后面** |
| `memory_order_acquire`（用在**读**） | 获取 | 这条读**之后**的所有读写，不许被重排到它**前面** |
| `memory_order_seq_cst` | 顺序一致 | **默认值**。所有线程看到的所有 seq_cst 操作，是**同一个全局顺序** |

```cpp
g_flag.store(1, std::memory_order_release);        // 写，带 release
int v = g_flag.load(std::memory_order_acquire);    // 读，带 acquire
g_x.store(1, std::memory_order_relaxed);           // 写，不约束顺序
g_y++;                                             // 不写第二参数 = seq_cst（最强、最贵）
```

**release / acquire 是成对用的**：一个线程 release 写、另一个线程 acquire 读到了那个值，
那么 **release 之前的所有写，acquire 之后都看得见**。这叫「建立了同步关系」。

### 2.3 今天的练习（你自己写，我只给骨架）

经典的「store buffer」实验。两个线程：

```cpp
std::atomic<int> g_x{0}, g_y{0};
int r1 = 0, r2 = 0;      // 两个线程各自读到的结果

void thread_1() {
    // 写 g_x = 1
    // 读 g_y 到 r1
}
void thread_2() {
    // 写 g_y = 1
    // 读 g_x 到 r2
}
```

**问题**：两个线程跑完后，`r1 == 0 && r2 == 0` 可不可能同时成立？

按「代码写的顺序」想：线程 1 先写 x 再读 y、线程 2 先写 y 再读 x，
至少有一个线程的写应该先发生，所以另一个必然读到 1 —— **看起来不可能两个都是 0**。

**要求**（按昨天立的卡点规矩，中途要编译，不许全写完才批）：

- **第一卡点**：`CASE_SEQCST`（全部用默认 seq_cst，不写第二参数）写完**先编译一次**，跑通再往下
- **第二卡点**：`CASE_RELAXED`（四个操作全用 `relaxed`）写完再编译一次
- **每个 case 跑 100 万轮**，统计 `r1==0 && r2==0` 出现了多少次
- 🔴 **两个 case 各写一行预测再跑**，预测写在源码注释里

> ⚠️ **我没跑过这个实验，所以我不给你结果数字。**明天我和你各跑一次对数据。
> 教科书上的结论是「seq_cst 下不可能、relaxed 下可能」，但**具体在你这台机器、这个编译器下
> 能不能观测到，必须跑出来才算数** —— 这正是你 10-22 撞到的那件事：

## 四、W8 主线续 · `compare_exchange` 开场（25min）

> 同样先给定义，不让你猜。

昨天 CASE C 证明了：**两个各自正确的原子操作，拼起来不是一个原子操作。**
那如果我需要「读到旧值 → 判断 → 写新值」这三步整体不被插入呢？

`compare_exchange_weak` / `compare_exchange_strong` 就是干这个的：

```cpp
bool ok = g_v.compare_exchange_strong(expected, desired);
// 含义：如果 g_v 当前 == expected，就把它改成 desired，返回 true
//       否则：不改 g_v，而是把 g_v 的当前值【写回 expected 这个变量】，返回 false
```

🔴 **第二行那个「写回 expected」是最容易踩的**：`expected` 是**引用参数，会被改**。
所以标准用法是个 `while` 循环 —— 失败了 `expected` 已经自动更新成最新值，再试一次。

**今天只要求你答两问（先不写代码）：**

**D1**：为什么它叫 `compare_exchange` 而不是 `exchange`？「compare」那一步不做会怎样？
**D2**：`weak` 版允许「明明相等也返回 false」（伪失败）。
既然有这种怪事，为什么还要用它、而不是永远用 `strong`？

## 上午 10:30-11:10 · C++（40min）

**主题：特殊成员函数的自动生成规则 —— 你以为编译器会给你的，它其实没给**

昨天你手写了 5 个（析构、拷贝构造、拷贝赋值、移动构造、移动赋值）。
今天反过来问：**哪些不写编译器会生成，哪些一旦你写了某个，另一个就悄悄消失。**
这是《Effective Modern C++》Item 17 的内容，也是 Chromium 里 `DISALLOW_COPY_AND_ASSIGN`
这类宏存在的根本原因。

### 闭卷先答（写进记录，不许先查）

1. 我写了拷贝构造，编译器还会给我生成**移动构造**吗？
2. 我写了析构函数，编译器还会给我生成**移动构造 / 移动赋值**吗？
3. 如果移动构造没被生成，`String b = std::move(a);` 这一行会编译失败，还是会悄悄变成别的行为？
   —— 这一问是今天的核心，**答完再写代码验证**。
4. `= default` 写出来的，和编译器自动生成的，是同一个东西吗？

### 任务：`F:\code\cpp-practice\week-02\day2_gen_rules.cpp`

不给你实现。给你**实验矩阵**，你自己设计一个能区分「调了哪个函数」的类，
然后把下面这张表跑出来填满：

| 类里显式写了什么 | `T b = a;`（拷贝）调了谁 | `T b = std::move(a);` 调了谁 |
|---|---|---|
| 什么都不写 | | |
| 只写析构函数 | | |
| 只写拷贝构造 | | |
| 只写移动构造 | | |
| 写了移动构造 + `= default` 的拷贝构造 | | |

自己查的（查完写进记录，不要问我）：
- `std::is_move_constructible<T>::value` 在哪个头文件，它返回 true 的时候能不能保证「走的是移动而不是拷贝」
- `= default` 写在类内和写在类外（`T::T(const T&) = default;`）有没有区别

#### 1. `std::variant` 是什么

一个**类型安全的 union**。`union` 是老 C 的做法：同一块内存按不同方式解释，
编译器不管你当前存的是哪个 —— 存了 `int` 按 `double` 读，是 UB，没人拦。
`variant` 把「现在存的是哪个」这件事**记下来**，存在内部一个下标里（`index()`）。

实跑数据：

```
sizeof(variant<int,double,string>) = 40        sizeof(string) = 32
default index = 0                              ← 默认构造 = 第一个备选，不是「空」
v = 42          → index=0  holds<int>=1 holds<double>=0
v = string("hi")→ index=2  get<string>=hi
```

- **40 = 32（最大成员 `string`）+ 8（下标 + 对齐）** —— 这解释了为什么 `variant` 的开销是
  「最大那个成员 + 一个下标」，**不是所有成员之和**。这点和 union 一样，也是它省内存的原因。
- `index()` 是 0/1/2，**按你写的备选顺序编号**，跟谁大谁小无关。
- **默认构造 = 第一个备选被构造**（index=0）。所以「空的 `variant` 不存在」——
  要么第一个备选能默认构造，要么你一开始就得给它 `std::monostate`。**这是它的第一个坑。**

#### 2. 取值三种写法，行为完全不同

```
std::get<double>(v)   → 抛 std::bad_variant_access（实跑 catch 到：bad variant access）
std::get_if<int>(&v)  → 返回 nullptr，不抛
std::get<0>(v)        → 按下标取，同样类型不对就抛
```

- **`get<T>` 拿的是引用**（不是拷贝），类型不对就抛异常。
- **`get_if<T>` 拿的是指针**，要传 `&v`，类型不对返回 `nullptr` —— **能进 `if`，不抛**。
- 这就是你 10-12 在 Electron 侧验过的同一件事换了个长相：
  **「会抛异常的接口」vs「返回可判空的接口」，两种错误处理风格。**
  C++ 标准库通常两个都给（`get` / `get_if`），Electron 侧一般只给一个。

#### 3. `std::visit` 是什么

**对当前真正存活的那个备选，调用你给的函数。** 你不用 `if` 判断类型了。

实跑：`v` 当时是 `string`，`std::visit(泛型 lambda, v)` → 打出 `visit sees: string hi`。

- 里面的 lambda 参数写 `auto&&`，编译器为**每个**备选各实例化一份，
  运行时只有活着的那份被调用。**这叫编译期分派，没有虚函数、没有运行时分发开销。**
- 所以 lambda 里必须能处理所有备选类型 —— 少一个就编译不过（这是好事，比漏 case 强）。
- 想对每个类型写不同代码，用 `if constexpr (std::is_same_v<...>)` 分开。

#### 4. 结构化绑定：`auto [a,b,c] = pt;` vs `auto& [a,b,c] = pt;`

实跑（`Pt{1, 2.5, "abc"}`）：

```
auto [a,b,c] = pt;        → a=1  b=2.5  c=abc
auto& [ra,rb,rc] = pt;  ra = 99  →  pt.x 变成 99   ✅ 改得动
auto  [ca,cb,cc] = pt;  ca = 7   →  pt.x 仍是 99   ❌ 改不动
```

- **`auto` 是拷贝一份再拆**，你改的是副本；**`auto&` 是给原对象起别名**，改的是本体。
- 这跟你 W1 学的「按值传参 vs 传引用」是同一件事，只是换了个语法外壳。
- **不用 `&` 的时候不会有编译错**，只是改了没用 —— 静默失效，比报错更坑。

### ③ `std::thread` 起步（15min，阶段二第一个新知识点）

**今天先只讲 + 只验一条，不写线程池。** 按 09-28 铁律：你没学过 `std::thread`，所以我先给定义。

**三条定义（直接给你，不要你猜）**：
1. `std::thread t(f, a, b);` —— **构造即启动**。线程对象一造出来，那个函数已经在另一个线程跑了。
   不像 Java 那种要再 `start()`。
2. `t.join()` —— 当前线程**停下来等** `t` 跑完。`t.detach()` —— **放手不管**，`t` 自己跑自己死，
   `t` 这个对象立刻不再关联任何线程。
3. **`std::thread` 对象析构时，如果既没 join 也没 detach → 直接 `std::terminate()`**，
   整个进程挂掉。这条是 C++ 标准规定的，不是 UB、不是泄漏 —— **进程当场死**。

**它是什么**（非主角概念，各一行）：
- `std::terminate()`：标准库的「立刻终止进程」函数，默认调 `abort()`。不走栈展开，析构不跑。
- `joinable()`：`std::thread` 的成员函数，返回这个对象现在还关不关联着一个活线程。

**你要做的实验（一个文件，`week-07/day1_thread.cpp`）**：
```
实验 A：造一个 thread 跑一个打印函数，正常 join，看输出顺序
实验 B：同一个函数，改成 detach，main 里什么都不等就结束，看输出还在不在
实验 C：造一个 thread，既不 join 也不 detach，让它出作用域 —— 看进程怎么死的
```
**⚠️ 实验 C 必须单独一个 `main` 或者放在最后**，而且 **每个 `cout` 后面要 `std::cout.flush()`**
或者用 `std::endl` —— 进程被 terminate 掉时缓冲区不刷新，不刷你会以为「什么都没输出」。
（这条坑我自己踩过，`0xC0000374` 那类崩溃会吞掉前面所有输出。）

### 6.3 本次学到的，与早上给的三条定义不同

**一、`detach` 不是「安全的放手」。** 它解绑线程与进程的生命周期，但线程用的全局资源（`cout`、全局对象）仍跟着进程走。detach 的线程活过 main，就是在用已经析构的东西。
教练对照实验：detach 的线程**不碰 cout**（只改一个全局变量），其余完全相同 → 10 次全部 `exit=0`；碰 cout 那版 → 10 次崩 5 次。

**二、退出码相同不代表原因相同，退出码定不了位。**
test2 崩和 test3 崩**退出码一模一样**，都是 `0xC0000409`，但 test3 是 thread 析构未 join/detach → `std::terminate`，test2 是向已析构的 `cout` 写入。
崩溃码要分清：`0xC0000409` = terminate/栈检查，`0xC0000005` = 访问越界（`shared_ptr` 那题遇到的是后者）。

**三、「跑一次正常」不等于对。** 并发类 bug 必须连跑多次。以后这类题交卷要跑 10 次再贴。

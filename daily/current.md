### 项 2 · ABA 问题开场（25min）

**这是你没学过的知识点，按规矩我先讲，再让你验。**

**ABA 是什么**：CAS 的判据是「**值还等不等于我读到的那个**」。
但「值相等」**不等于**「中间没人动过」。
值可以从 `A` 变成 `B` 再变回 `A` —— 你的 CAS 看到还是 `A`，于是**认为没人动过，成功写入**。
**可中间那段发生的事，你全错过了。**

对计数器（昨天你写的那个）**无害**：数字就是数字，`5` 还是 `5`，没有别的含义。
对**指针**就是**致命**的：指针值相同，但它指向的那块内存**可能已经被释放、又被重新分配给了别人**。
→ 这正是 Chromium 里无锁结构必须处理的那一类问题，也是你部门会见到的崩溃形态。

**K1（填表，不写代码）**：把下面这个时序补完。
无锁栈，`top` 是 `atomic<Node*>`，线程 1 要 pop：

| 步 | 线程 1 | 线程 2 | `top` 的值 |
|---|---|---|---|
| 1 | 读到 `top == 节点A`，记下 `next = A->next`（= 节点B） | — | A |
| 2 | **被操作系统挂起** | pop 掉 A，再 pop 掉 B | ___ |
| 3 | 仍挂起 | `delete A`（A 这块内存还给系统） | ___ |
| 4 | 仍挂起 | `push` 一个新节点，**系统正好把刚才 A 的那块内存又分配给它**，地址相同 | ___ |
| 5 | 醒来，执行 `CAS(top, A, next)` | — | ___ |

**K2**：第 5 步那个 CAS **成功还是失败**？为什么？
**K3**：CAS 成功之后，`top` 指向哪里？**那个地方现在还是合法节点吗？** 说清为什么。

### 项 3 · 无锁计数器完整版（`ThreadSafeCounter` 前置）

把昨天的 `day3_cas_counter.cpp` 升级成一个**类**：`week-08/day4_lockfree_counter.cpp`

**接口骨架**（这是骨架，不是实现 —— 函数体你自己写）：

```cpp
class LockFreeCounter {
public:
    LockFreeCounter();                  // 初值 0
    void Increment();                   // 必须走 CAS 循环
    void Add(int delta);                // 加任意值，同样走 CAS 循环
    bool TryDecrementIfPositive();      // 只在当前值 > 0 时减 1；成功返回 true，否则 false
    int  Get() const;
private:
    std::atomic<int> value_;
};
```

**三条约束（和昨天同款，违反直接退回）**：
1. **不许用** `fetch_add` / `fetch_sub` / `operator++` / `operator--`
2. **不许用**任何锁（`mutex`、`lock_guard`）
3. `Increment` / `Add` / `TryDecrementIfPositive` 三个函数里，**真正改值的那一步必须是 `compare_exchange_weak`**

**🔴 中途卡点（不许全写完才给我看）**：
- **第一卡点**：写完构造函数 + `Increment()` + `Get()` 就**先编译一次**，跑通了贴给我，我批完你再往下写。
- **第二卡点**：写完 `Add(int)` 再编译一次，贴给我。
- 最后再写 `TryDecrementIfPositive()`。

**`TryDecrementIfPositive` 是今天真正的难点**，提前说清难在哪（不给实现）：
前面三个函数「该写什么值」是算出来的；**这个函数要先判断「该不该写」**。
判断和写入之间有时间差，而别的线程可能在这个缝里把值改掉。
→ **判断必须在循环内部，CAS 失败后要重新判断，不能只重新算。**

**验收**：4 个线程各 `Increment()` 25 万次，总数必须是 `1000000`，连跑 5 次。
另外单独测 `TryDecrementIfPositive()` 在值为 `0` 时返回 `false` 且 `Get()` 仍是 `0`。

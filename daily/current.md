### 3.1 先讲定义（你没学过，按 09-28 铁律先给答案再验）

五层各是什么，下面每条都是我从 `E:/code/browser/src` 各层 `README.md` 原文翻的：

| 层 | 官方定义（译） | 一句话判据 |
|---|---|---|
| `content/` | 用「多进程 + 沙箱」渲染一个页面所需的核心代码，**包含全部 Web 平台能力（HTML5）和 GPU 加速**；**不含** Chrome 自己的功能（扩展、自动填充、拼写检查） | **「任何浏览器都得有」的那部分** |
| `chrome/` | Google Chrome 的**应用层**。和 `content/` 不同，这里放的是「做一个具体产品」的代码，带主观 UX 取向 | **「Chrome 这个产品才有」的那部分** |
| `components/` | 被 Chromium **一个以上的地方**共用的功能/子系统（例如 `//chrome` 和 `//ios/chrome` 共用，或多个 content 嵌入方共用） | **「两处以上都要用，所以提出来」** |
| `extensions/` | 可复用的扩展系统模块，实现 Chrome 扩展体系的核心，**可以挂在任何 content 模块的宿主上** | **扩展机制本身** |
| `net/` | Chrome 的网络栈 | **网络协议/URL 那一层** |

**分层存在的原因**（`content/README.md` 原文的动机段）：代码长大后功能总是挂错地方，
造成**分层违例（layering violation）**和本不该有的依赖。
把「渲染页面的核心」单独切成 `content/`，就是为了划一条硬线。

> 「分层违例」= 底层代码反过来依赖上层代码。
> 举例：`content/` 里出现 `#include "chrome/..."` —— 那就是违例，`content/` 不该知道 Chrome 存在。

```

  by_hand 与 by_guard 两个函数体**逐条指令完全相同**：
      sub rsp,40 / lea rcx,g_mu / call _Mtx_lock / test eax,eax
      / inc DWORD PTR g_counter / lea rcx,g_mu / jmp _Mtx_unlock
  lock_guard 的构造与析构**一个 call 都没剩**，全部内联。不是「差不多快」，是同一份机器码。
  📌 教练补他没说的那层：**真正的区别不在正常路径，在异常路径。**
     ++g_counter 若抛异常，手写版 unlock() 被跳过（与 R4 的 return 同一个坑）；
     lock_guard 靠栈展开照样析构。这就是「零成本抽象」：正常路径零指令差、异常路径多一层保障。

Q2（跑 1000 次全对为什么不是判据，两条判据）：
```

### 五、欠账 13 · W3-2 扩容计数纸面推导 —— ✅ 清账（10-26 15:5x，挂 3 周、排过 4 次）

> 原答案被判不过的理由：写的是「搬运次数成倍上涨」—— 形容词，不是推导。本次要出数。
> 题面一字未改（09-21 规矩）。n = 1024，纸上算不许跑代码。

```
① 扩容次数        本人答 10        ✅ 教练实算 10
② 翻倍总拷贝次数  本人答 1023      ✅ 教练实算 1023
③ 平均每次拷贝    本人答「大约1次」 🟡 精确值 1023/1024 = 0.999，**小于 1**
④ 每次+1 总拷贝   本人答 523776    ✅ 教练实算 523776（差 512 倍）
⑤ 说明了什么      见下，第一版驳回、重答过
```

**③ 的订正（不是抠字眼）**：①②④ 都给了精确数，③ 突然回到「大约」，而这个「大约」
恰好盖住了最关键的性质 —— 拷贝总数 1023 = 2¹⁰ − 1，**永远比 n 少 1**。
不是「接近 1」，是**严格小于 1 且不随 n 变大**；n 到 100 万仍是 0.999…。
**这才是「摊还 O(1)」的内容**：不是「平均下来差不多是常数」，是**有一个与 n 无关的上界**。

**⑤ 第一版（驳回）**：「翻倍把总拷贝次数从 O(n²) 降到 O(n)，使每次 push_back 的
摊还成本为 O(1)」 —— 三个符号全对，但**这是结论的名字，不是推导**。
追问：④ 算出 523776，这个数怎么就是 O(n²) 了？答案里没有 n(n−1)/2 这个形式。
⚠️ 本日第 4 次同一形态：**有结论的名字，没有结论的来源**（R3、Q2、W3 天气、⑤）。
按 09-20 规矩，记录里没标他掌握过 O(n²)/O(n)/摊还的推导，一律按未掌握处理。

**⑤ 重答（✅ 过，全程禁用 O(n)/O(n²)/摊还三个词）**—— 本人原文：

> **每次容量 +1**：每插入一个放不下的新元素，就搬一次已有的全部元素。
> 插入第 2 个：容量 1→2，拷贝 1 个；插入第 3 个：2→3，拷贝 2 个；……
> 插入第 1024 个：1023→1024，拷贝 1023 个。
> 所以一共加 1023 项：1+2+3+…+1023 = 1023×1024/2 = **523776**
>
> **每次容量翻倍**：**扩容后会空出一批位置，填满之前都不用再搬。**
> 所以一共只加 10 项：1+2+4+8+16+32+64+128+256+512 = **1023**

🔴 **承重句是他自己写的**：「扩容后会空出一批位置，填满之前都不用再搬」——
直接解释了项数为何只有 10：空出的位置越来越多，下一次搬运被推得越来越远。
**不是教练给的措辞。**

📌 教练补他算式里已有、但未点破的一层：
**1+2+4+…+512 = 1023，比最后一项 512 的两倍还少 1。**
后面全部项加起来都超不过最后一项的 2 倍 → 总拷贝数永远被 2n 卡住，n 多大都一样。
这就是 ③ 那个 0.999 为何不随 n 变化。

**定级**：①②④⑤ 过。⑤ 为换实例重答（禁符号、要算式），记 **M2**；
③ 的「与 n 无关的上界」属教练补充，未经闭卷，不计掌握，下次复测必考。

## 二、掌握（闭卷自答 · 本人原话，未润色）

### 上午 C++（10:21 / 11:07 / 11:30 三轮）

> 1.unordered_map 要 hash +operator== 因为除了要用 hash 算出是在哪个桶里，还有用==判断是不是当前 key
> 1.因为有可能两个不同的 key hash 以后的值是一样的，这就是 hash 碰撞
> 2.unordered_map::insert 仅限发生重散列的情况失效（如果操作后新的元素数量大于原
>   max_load_factor() * bucket_count() 则会发生重散列）
> 2.一个 unordered_map 迭代器除了能解引用拿到元素，还承诺你能 ++ 走遍整个容器。
>   rehash 改了遍历顺序，那这个承诺不在了；指针没有这个承诺
> 3.n 个元素的树高是 log(n)，找位置走过的结点就是层数，所以是 O(log(size()))，
>   "只改指针所以 O(1)"错在 我只考虑了修改的代价，没有考虑查找的代价
> 4.我翻了，没找到，用 map 的地方很多，非 map 不可的情况我不清楚
> 4.我做了实验了，100 万次大概差 12 毫秒 同时最多存在 7 个 不是速度
> 5.8 变成了 512 没变 vector 地址变了

### `string_view` 三问

> 1.是编译器构造的，构造他需要花费空间和时间，还拷贝了一份常量。
>   换成 void f(std::string_view s) 后，不需要构造 string 了
> 2.string_view 只有指针指向数据，数据原来是谁的，谁依然拥有数据
> 3.string_view 不管字符串有没有 \0，他只有一个指针和大小，原来的数据有 \0 他就有，没有就没有
> 3.打印这个证明了 string_view 不保证返回以 \0 结尾；
>   string_view 应该用 std::cout 或者是 printf("%.*s", (int)sv.size(), sv.data())

### npm / `import`·`export`

> 1.和 scripts 里的第二行对上了 → 是交给命令行执行吗？因为命令行直接原样输出了：node -e "console.log(1+1)"
> 2.export default Hello 导出了主要的函数，import App from './App.tsx' 拿了这个主要函数并进行了重命名 App，
>   所以无论 App.tsx 怎么改名字，这里拿到的都是它的 default 导出
> 3.{ StrictMode } 是指的名称一致的 'react' 里面的导出，app 是对 default 导出的重命名，可以一致也可以不一致

### 三层链整链（提级判定通过的那段原话）

> 1.沙箱掉了（其余两层还在）——攻击者拿到了渲染进程的 os 权限，可以执行任意代码和操作
>   沙箱在，contextIsolation 掉了——攻击者拿不到主进程的权限，但拿到 preload 的权限，
>   他还能改 Array.prototype.push 这类内置方法，然后等高权限代码来调用他。
>   前两层都在，contextBridge 写错了——可能会暴露给攻击者一些权限大的接口，

### `string_view_probe.cpp` 最终版 —— 教练实跑（`cl /utf-8 /EHsc /std:c++17`，零警告，exit 0）

```
p : 000000922E7CFE60          <- 栈上（SSO，capacity 15）
p..capacity() :15
str : 123456789
strlen :9
str size :9
p : 000001D76AF0F3A0          <- 堆上，换了内存
str : ���j�                   <- 悬垂视图，读的是已废弃的旧 buffer
223                           <- std::cout << str1，正好 3 个字符
```

三处闭环：①`p.data()` 从栈地址跳到堆地址 = 真的重新分配了；②`str` 乱码 = 悬垂；
③`std::cout << str1` 打出 3 个字符，而上一版 `printf("%s")` 打出 32 个 ——
**同一个 `string_view`，换个输出方式就正确了**，问题不在 `string_view` 在怎么读它。

### `continer_timer.cpp`（本人自写的扩展实验）—— 教练实跑

```
耗时: 28 毫秒     <- std::map<RuntimeBinaryKind,int>，find 100 万次
耗时: 18 毫秒     <- std::unordered_map，同上
```
差 **10ms**，与本人自测「约 12 毫秒」同量级（机器抖动范围内）。
单次差十几纳秒，而这两个 map 一生的总查找次数是个位数 → 本人判定「能换不该换」成立。

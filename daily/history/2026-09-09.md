## 掌握

### 1. MyUniquePtr 实现要点

（用自己的话写：移动构造怎么"偷"、移动赋值多做了什么、release 和 reset 的区别）
移动构造是直接把其他对象的资源直接拿过来使用，并把其他对象的资源设为 nullptr。
移动赋值是先把自己的资源释放，再把其他对象的资源直接拿过来使用，并把其他对象的资源设为 nullptr。
release是放弃资源的所有权，把资源指针设为 nullptr。并且返回资源指针。
reset是先释放自己的资源，再把传进来的资源设置给自己的资源指针。

### 2. `operator bool()` — 类型转换运算符

（自己写：它是什么？和 `operator()()` 有什么区别？为什么加了 explicit 之后 `if (up)` 还能用？）
`operator bool()` 是类型转换运算符，用于将 MyUniquePtr 转换为 bool 类型。
`operator()()` 是调用运算符，可以把 MyUniquePtr 当作函数调用。
explicit 关键字可以防止隐式类型转换，避免编译器错误的转换。

### 3. `explicit` 关键字

（自己写：防什么？不加会发生什么荒谬的事？什么场景必须加？）
`explicit` 关键字可以防止隐式类型转换，避免编译器错误的转换。不允许编译器替我们决定如何转换。
凡是转换后语义会变模糊的地方（所有权、资源、单位）都该加。
例如下面的例子（如果使用explicit关键字,下面的代码会发生所有权转移。可能会引起资源泄漏。）：
MyUniquePtr<Widget> up = new Widget(1);   // 裸指针悄悄变成智能指针
void func(MyUniquePtr<Widget> p);
func(new Widget(2));   

### 4. `noexcept` 关键字

（自己写：承诺什么？违约后果？为什么移动构造必须加——和 vector 扩容有什么关系？）
`noexcept` 关键字：承诺当前方法不会出现异常。
移动构造必须加，移动构造只做两件事——偷指针、置空源指针。都是指针赋值，不分配内存不调用可能抛异常的代码。承诺不抛异常是安全的。
与vector扩容的关系：
因为 vector 扩容时会调用移动构造函数，而移动构造函数可能会抛出异常。
因为 vector 扩容时有两种情况：1.直接移动，2.复制构造。
如果移动构造函数没有加 noexcept 关键字，那么 vector 扩容时就会选择复制构造。
如果移动构造函数加 noexcept 关键字，那么 vector 扩容时就会选择直接移动。
性能差距很明显。

### 5. electron

## 1. IPC 路由机制
helloName : (nameString) => ipcRenderer.invoke('helloName', nameString)中'helloName' 是路由键不是方法名，换成任意的都可以，比如换成‘aaa’
## 2. IPC 只能传可序列化数据
直接返回nameString失败
## 3.handler 签名规则
ipcMain.handle 的回调第一个参数永远是 event，数据从第二个开始
## 4.参数传递四层链
页面 → preload → invoke → main，任何一层漏传就断
## 5.JS 动态弱类型 vs C++ 静态强类型
js的类型是不固定的 可能是 数字 也可能是字符串 也可能是对象
## 6.contextBridge 的安全模型：为什么不直接把 ipcRenderer 给页面
如果直接暴露给渲染进程，网页就能通过他发送很多不应该发送的信息给主进程，可能被黑客找到漏洞，攻击我们的电脑，
## 7.排查问题
1.渲染进程报错看 DevTools Console（Ctrl+Shift+I）
2.主进程可以调试

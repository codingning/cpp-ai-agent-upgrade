> 「编译器会在所有可能退出的路径前插入析构调用，比如：提前 return / 抛出异常，因为很多资源不能等到进程退出再释放，比如锁/文件，其他进程/线程也有可能要用。」

- **第二问 ✅ 结账**。「锁/文件，别人还要用」是他自己的例子，不是 10-16 的措辞 —— 这是标「想」应该长的样子。
- **第一问 半对**。他答的全是「函数的退出路径」。教练实跑（MSVC x64 `/std:c++17 /utf-8 /EHsc`，`BUILD_EXIT=0 RUN_EXIT=0`）：

```
== n=1 ==
ctor 1
ctor 2
dtor 2      <- 临时量 T(2)，take() 返回后那一行就死
ctor 3
dtor 3      <- 内层 { } 结束就死
ctor 4
dtor 4      <- delete 触发
ctor 99
-- f end --
~Holder
dtor 99     <- 成员 m，随父对象析构
dtor 1      <- 作用域对象，函数真出口
```

`dtor 2` / `dtor 3` / `dtor 4` 三条**全部打在 `-- f end --` 之前**，一个都不在函数退出路径上。

正确说法：**编译器在每个对象自己的生命周期结束处插入析构调用**，四类位置 ——
①作用域结束（含提前 return / 异常；注意是「作用域」不是「函数」，看 `dtor 3`）
②临时量：所在完整表达式结束 ③成员/基类子对象：父对象析构时 ④堆对象：`delete` 触发（这一类编译器不插，是人调的）

**差别不是记少了，是把这件事挂在「函数出口」上，正确的挂点是「对象生命周期」。挂错点，`dtor 2`/`dtor 3` 这种永远推不出来。**
**判：R1 第二问结账，第一问半对，不退回重答（给的是自己的话不是复述），挂一条改口：不说「函数退出路径」，说「对象生命周期结束处」。下次问直接看他用哪个词。**

### ⚠️ 本人一处结论错 + 证据用反（记本人账，判据第 N 次）

教练追问：`auto& [ra,rb,rc] = pt;` 是「三个各自独立的引用」还是「对 `pt` 整体起别名再拆名字」？

**本人答「三个各自独立的引用，`&ra` 是证据」—— 结论错，且证据无分辨力。**

`&ra == &pt.x` 两种假设都会产生 → **这个实验分不开那两件事**（老坑「实验要有分辨力」）。

**教练实跑能分开的对照组**（`$LOCALAPPDATA/Temp/sb2`，同套编译参数，`BUILD_EXIT=0` `RUN_EXIT=0`）：

```
is_reference<decltype(ra)>       = 0     ← ra 不是引用类型
is_reference<decltype(real_ref)> = 1     ← 同程序里真正的 int& 对照组
is_same<decltype(ra), int>       = 1     ← ra 的类型就是 int
is_same<decltype(ra), int&>      = 0
sizeof(ra) = 4   sizeof(pt.x) = 4
&ra=...FE68  &rb=...FE70  &rc=...FE78
&pt=...FE68  &pt.y=...FE70  &pt.s=...FE78     ← 严丝合缝等于 Pt 的成员布局
&a =...FE98  &b =...FEA0  &c =...FEA8         ← 不带 & 那组整块换地方
```

**真实机制（教练给，本人未独立推出，不计掌握）**：`auto&` 那行先对 `pt` **整体**建一个

**咬人处**：`decltype(ra)` 给 `int` 不给 `int&` —— **改得动本体，但类型不是引用类型**，
写模板时拿绑定名字推类型会推错。

**问：这四个为什么抽不进那个纯虚基类？**（不许答「因为只有 CEF 需要」= 现象非理由）

### 本人执行情况

- ✅ **三条查证命令全部跑对**，数据完整贴回（`main.cc:397` 唯一调用点 /
  `WebViewInit` 三个调用点含 `EnsureWebViewInitialized` / `main.cc:393-404` 那段 `if HasSwitch("type")`）
- ❌ **结论答不出**：本人原话「我不知道为什么他们抽不进去」
- → 按 09-28 铁律（没学过的先讲定义和答案），教练直讲。**因此这一问不计为本人掌握，挂 10-16 上午闭卷重答。**

### 教练所给的答案（本人未独立推出，不计掌握）

**缺的概念：纯虚函数要有「对象」才能调。** `v->Navigate(...)` 那个箭头是整件事的前提 ——
对象里存虚表指针，运行时查表分派。**没有对象 → 没有虚表指针 → 虚函数机制启动不了。**

| 函数 | 调用时机 | 为什么抽不进 |
|---|---|---|
| `WebViewRunChildProcess` | `main.cc:397`，`if HasSwitch("type")` 分支内，**跑完直接 `return exit_code`，后面 main 一行不走** | 带 `--type=` 的进程 = CEF 子进程（renderer/gpu/utility），**它这辈子不会创建任何 WebView 对象** |
| `WebViewInit` | `zip_main_window.cc:1553`（函数名 **`EnsureWebViewInitialized`**，被 1567/1631 调两次） | 这是**全进程一次性**的 CEF 库初始化。一个进程可有 5 个 WebView 但 CEF 只能初始化一次，且**必须发生在第一个对象被创建之前** → **顺序倒置** |
| `WebViewMessageLoopWorkOnce` | 进程级消息泵 | 同上，进程范围 |
| `WebViewIsCefEnabled` | `webview.cc:34`，**`WebView::Create()` 自己在调它**决定 `new CefWebViewImpl()` 还是 WebView2 | 它用来决定**造哪种对象** → 做成成员函数就是鸡生蛋 |

**一句话**：这四个的调用时机**全部在「WebView 对象存在」这个区间之外** ——
在子进程里 / 在第一个对象之前 / 用来决定造哪个对象。
**抽象基类只能描述「一个对象能做什么」，描述不了「进程该怎么起」。**

**对照（真对照，不是新学 Electron）**：Electron 里 `app.whenReady()` 挂在 `app` 上不挂在
`BrowserWindow` 上。`app` 管进程、`BrowserWindow` 管窗口。q-framework **没有 `app` 这个对象**，
所以这四个只能裸着当自由函数放 namespace 里。

### 🏆 追问本人独立答对，且答得比教练问的准

教练追问：`Delegate` 那 9 个纯虚也是别人实现的，为什么它们能进抽象基类？

**本人原话**：「这两个完全不是一回事吧，上面四个是没有对象去实现，
而 `Delegate` 那 9 个纯虚函数是不知道派生类需要怎么实现，所以抽象了」

**✅ 判过。** 他抓住的正是分界：**缺实现 → 纯虚函数能解决；缺对象 → 纯虚函数无能为力。**
`Delegate` 不缺对象（宿主继承它，`Init` 时把 `this` 传进来，`WebView` 一直握着活的
`delegate` 指针，`delegate->HandleAppCmd(...)` 箭头有东西可用）。

**教练补的只是名字**（他的老形态：知识在脑子里，缺名字）：
- `Delegate` 那 9 个 = **依赖倒置**，方向**外→内**（别人实现、`WebView` 调用）
- `WebView` 那 11 个 = **多态**，方向**内→外**（你调用、两套实现响应）
- **同一个头文件里两套抽象机制，方向相反。** 面试能把这两套分开讲 = 第二层答满
  （多数人只会说「为了解耦」）

**第二层四问全部结账。** 第 4 问是教练讲的 → 挂 10-16 上午闭卷重答；
`Delegate` 这一问是他自己推的 → **计入掌握**。

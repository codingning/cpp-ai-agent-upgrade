**P1 · 把你写的 `LockFreeCounter` 再看一遍**（15min）：
- 读你 10-30 的 `day4_lockfree_counter.cpp`，闭卷讲清**三件事**：
  1. `Increment()` 为什么是 `do { ... } while (!cas)` 而不是 `while (!cas) { ... }`？
  2. `Add(int delta)` 和 `Increment()` 的循环体**有什么不一样**？为什么？
  3. `TryDecrementIfPositive` 的 `while(1)` 为什么**没有退路**只有 `return`？

**P2 · 加一个方法 `bool TryIncrementIfBelow(int limit)`**（45min）：
语义：**只在当前值 < limit 时加 1**；成功返回 `true`，否则返回 `false`。
这是 `TryDecrementIfPositive` 的对称操作，用来做「限流名额」/「连接池上限」。

**三条约束照旧**：
1. 不许用 `fetch_add` / `operator++`。
2. 不许用锁。
3. 真正改值的那一步必须是 `compare_exchange_weak`。

**🔴 中途卡点**：
- **第一卡点**：写完编译一次，贴我 `CL_EXIT=0`，我批完你再写测试。
- **第二卡点**：补测试 main——8 线程各调 1000 次 `TryIncrementIfBelow(500)`，`Get()` 必须 ≤ 500，返回 `true` 的总次数必须正好 500。连跑 5 遍，自己贴真输出，我自己也会跑。

**提前说清难点**（不给实现）：
- 和 `TryDecrementIfPositive` 对称，判断在循环内。
- 边界条件：`limit=0` 时任何调用都返回 `false`，`Get()` 保持 0。
- 常见坑：`m + 1 < limit` 和 `m < limit` 顺序别写反。

**验收**：末值 ≤ `limit`、`true` 次数 = `limit`、`false` 次数 = `总调用数 - limit`，一次超限都不许有。

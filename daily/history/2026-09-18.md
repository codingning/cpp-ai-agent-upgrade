### Q3：抑制关系表（重答后）

> 写析构 → 移动构造：影响，移动被抑制，退化成拷贝
> 写拷贝构造 → 移动赋值：影响，移动被抑制，退化成拷贝构造
> 写移动构造 → 拷贝构造：影响，拷贝构造和拷贝赋值被 delete
>
> 首答只写「会影响」，未说明影响形态；经指出后重答，三格全对。
> 关键区分：前两格是**静默退化**（编译过，性能没了），第三格是**硬删除**（编译失败，反而安全）。

### Q4：std::move 静默退化成拷贝的情况（重答后）

> 1. `const T a; T b = std::move(a);` —— `std::move` 对 const T 取出的是 `const T&&`，
>    绑不到 `T&&` 形参，重载决议退到 `const T&`，走拷贝构造
> 2. 实现了析构/拷贝构造/拷贝赋值中任意一个 → 移动构造和移动赋值被抑制
> 3. 移动构造没标 `noexcept` → vector 扩容时为保证异常安全，放弃移动改用拷贝
>
> 首答只有 2 条且无例子；第 3 条经教练实跑对照实验后补上。

### Q5：Menu 是全局一份还是每窗口一份？

> **全局一份**（猜的是「每窗口一份」，猜错）。
> 官方文档：「Each app only has a single application menu at a time」。
> Windows 上应用菜单渲染在每个窗口顶部，所以外观上像每窗口一份，但共享同一个 Menu 对象。
> 实验证据：删掉 menu.js 里的 File 菜单项 → 所有窗口的菜单里该项同时消失。

**方法论提示（这是今天第三次同类问题）**：你看到「命令超时」就下了「push 失败」的结论，
但超时这个现象既可能来自「没推上去」，也可能来自「推上去了但连接没干净收尾」——
**两种假设都能产生同一个现象，所以它没有分辨力**。分辨方法只要一条命令：
`git ls-remote origin master` 对一下 hash。今天「实验缺分辨力」已经是第三次，
前两次在 require 位置和菜单份数上，这次在 push 上，说明这不是 C++ 问题，是判断习惯问题。

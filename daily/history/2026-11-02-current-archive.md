## 三、答题区（直接在下面填）

```
〇之二 10-31 醒了第一件碰的东西（一个词）：出门


M1 两线程时序（A/B 逐步写）：如果把if (m <= 0) return false; 挪到循环外只判一次，「A: load 读到 1 → B: load 读到 1  → A: 判断 m <= 0 成功，进入while循环 → B: 判断 m <= 0 成功，进入while循环→ A: value_-1成功， 值变成 0 退出  → B:value_-1 失败， 再次循环， 0-1变成了 -1」


R-1 ①std::ref + const& ：是源对象本身，不能改到源对象，没有被挡吧，因为const所以不能改
R-1 ②裸传 + const& ：不是源对象本身，不能改到源对象，被挡在接受环节
R-1 ③std::ref + 按值形参：不是源对象本身，不能改到源对象，接受的时候是拷贝，被挡在传递环节
R-1 被挡在哪一步（传递 还是 接收）：上面都分别写了

R-2 两个 atomic 为什么还会读到不匹配（禁用「原子性」「一致性」）：因为atomic只能保证自己这个变量的操作是线程安全的，但是不能保证其他变量的线程安全。哪怕两个atomic变量，也不能保证一致。

R-3 CAS 循环三步：先读取当前值，再判断是否等于期望值，如果等于，就用新值替换当前值，否则回到第一步。
R-3 失败时期望值是谁改的：是当前线程

R-4 那一刀为什么落在 JS 执行之前（举一件启动阶段必须干的事）：启动阶段可能需要加载dll，也就需要读取文件的权限，而UNTRUSTED 下干不了。

R-5 翻倍扩容总搬运数（写算式）：1+2+4+8+16+32+64+128+256+512=1023
R-5 为什么永远超不过 2n：因为  1023 < 512*2 -1 也就是永远小于2n

O1 scoped_refptr.h：类似于shared_ptr，自己管理引用计数，当引用计数为0时，自动析构。但是我有一个疑问，注释中写，建议像使用unique_ptr一样使用scoped_refptr,除非是栈函数传递时，才直接传递值，否则使用move
O2 weak_ptr.h：弱指针，不会增加引用计数，也不会自动析构。
O3 bind.h：绑定函数，生成一个新的函数对象。
O4 string_number_conversions.h：字符串转换为数字，数字转换为字符串的一批函数。
O5 lock.h：锁，用于保护共享资源，防止多个线程同时访问。
O6 哪些标准库已有 / Chromium 为什么还要自己造：我只知道 标准库有shared_ptr,weak_ptr,itor, lock这几个，不知道有没有bind，也不清楚为什么chormium要自己实现一套新的
```

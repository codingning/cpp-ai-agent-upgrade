## 四、证据（教练实跑/实查）

### 探针 1：迭代器/地址稳定性（`iter_probe.cpp`，MSVC `/std:c++17`）

```
[map]  find(2) 地址 ...80C40 → 插 100 个 + erase(4) 后地址不变、值仍 20、++it 正常跳到 100
[unordered_map] bucket_count 8 → 512（真发生 rehash），但 key=2 地址不变，旧地址仍读出 20
[vector] cap 4 → 6（⚠️ MSVC 是 1.5 倍，不是 2 倍），v[2] 地址 ...A898 → ...A9D8 变了
[vector] reserve(10) 预留后 push 不扩容那版：地址不变 ✅
```

### 探针 2：key 类型要求（`key_probe.cpp`，教练 21:34 两分支各编一次）

```
默认编译：__cplusplus = 199711   ← ⚠️ MSVC 不加 /Zc:__cplusplus 时的假值，不代表在用 C++98
加 /Zc:__cplusplus：__cplusplus = 201402
[1] map<enum class,int>            OK, size=1
[2] unordered_map<enum class,int>  OK, size=1, hash=12478008331234465636   ← 编译通过
[3] map<MyStr,int>（只有 operator<）OK, size=1
TEST_STRUCT_UMAP 分支（自定义 struct 只有 < 和 ==）：
  xhash(118): error C2064: 项不会计算为接受 1 个参数的函数
  xhash(118): error C2056: 非法表达式        CL_EXIT=2
```

→ enum class 两边都能用（C++14 起标准要求 enum 有 `std::hash` 特化）；
自定义类**只有 map 现成能用**。**若本人据 `199711` 推过任何结论，作废重推。**

### q-framework 实证坐标（教练实查，非举例）

- `std::map` 1473 处 / `std::unordered_map` 638 处（已排除 `base/`）
- `ui/dui/Control/UIMenu.cpp:1417` `std::map<CDuiString, bool>` —— `CDuiString` 是 DuiLib 自有类，
  `std::hash` 不认识它 → **「选 map 是成本考量不是性能考量」的真实证据**

### loadFile 两版对照（本人实跑，教练核 dist 与配置）

| | 无 base | 有 `base: './'` |
|---|---|---|
| `dist/index.html` 里的 src | `/assets/index-BjGiThP1.js` | `./assets/index-DMtXDnJR.js` |
| 结果 | **白屏** | **不白屏，React 真渲染出来** |
| 控制台 | `Failed to load resource: net::ERR_FILE_NOT_FOUND` | 只有 CSP 开发警告 |

**结论（两条，都被证据分开了）**：
1. **无 base 白屏 ≠ CORS**，是 `/assets/...` 绝对路径在 `file://` 下被解析到盘符根 → 文件不在那
2. **有 base 不白屏 ⇒ Electron 对自己的 `file://` 放行了 `type="module"`**
   —— 同协议同 module 脚本，浏览器双击被 CORS 拦（09-22 本人实测），Electron 里能跑

**自洽性交叉核对**：报错里的文件名 `index-BjGiThP1.js` 与今天 build 产物 `index-DMtXDnJR.js`
**哈希不同** → 证明他确实重新 build 了两版，不是改配置没重跑。

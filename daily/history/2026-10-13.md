## 三、掌握（闭卷自答，均为本人原话摘录，教练不代写）

### Q1 · `~A` 然后 `~C`，为什么是这个顺序？ ✅ 独立答对（今日质量最高）

> 本人原话：「本来 `c_` 应该先被析构，但是因为 `a_` 里面还持有他，计数没有归零，
> 所以就开始析构 `a_`，A 计数归零，然后直接被析构，然后 c 的计数也归 0，然后是 `~C`。
> 作用域里 `a_` 的 `use_count` 是 1，`c_` 是 2」

两个计数全对：`a_` = 1（只有局部变量持有，`C` 里那个是 `weak` 不计数）、
`c_` = 2（局部变量 + `a_` 的成员）。作用域逆序销毁先动 `c_` 降到 1 不死，再动 `a_` 降到 0
→ `~A` → A 的成员跟着析构 → `c_` 归 0 → `~C`。**链条完整，自己推的。**

### Q2 · 为什么用 `weak_ptr` 不用裸指针 `A*`？ ⚠️ 第一轮错，第二轮对

- **第一轮（16:56）❌**：「因为 `weak_ptr` 不用自己管理资源，裸指针还需要我们自己管理资源的申请和释放」
  → **无分辨力（今日第 2 次）**：这个场景里裸指针也不管资源（只观察、不 `delete`），
  环照样断、析构照样打，这个理由在两种写法下都成立，分不开。
- **第二轮（17:24）✅ 结账**：「`weak_ptr` 比裸指针多提供了一个 `lock()`，
  可以在使用前进行检查，能知道对象是否还活着，而裸指针不行」

**教练实跑探针（本机，同一条编译命令，实测不是推测）**：
```
[alive] w.expired()=0  w.use_count()=1  lock()==nullptr? 0  raw==nullptr? 0
~A
[dead ] w.expired()=1  w.use_count()=0  lock()==nullptr? 1  raw==nullptr? 0
raw 的地址值还在: 0000022FF9F1E5C0   ← 它不知道对象已经死了
```
